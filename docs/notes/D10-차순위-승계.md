# D10 — 차순위 승계: 결제 실패 시 자동 재지정

## 핵심 변경

결제 실패 시 다음 최고가 입찰자에게 자동으로 낙찰을 승계하는 흐름 구현.

### 흐름

```
PaymentFailedEvent 수신
  → bid-service gRPC ReassignWinner(auctionId, failedBidderId)
    → 현재 WINNER를 DISQUALIFIED로 전이
    → 다음 최고가 OUTBID 입찰을 WINNER로 승격
  → 차순위 있음: resetForReassignment + assignWinner → WinnerReassignedEvent 발행
  → 차순위 없음: resetForReassignment + fail → FAILED(유찰)
```

### 연쇄 승계

C(300) → B(200) → A(100) 순서로 입찰된 경매에서:
1. C 결제 실패 → C=DISQUALIFIED → B가 WINNER → WinnerReassignedEvent
2. B 결제 실패 → B=DISQUALIFIED → A가 WINNER → WinnerReassignedEvent
3. A 결제 실패 → A=DISQUALIFIED → OUTBID 없음 → FAILED(유찰)

DISQUALIFIED 상태 덕분에 이미 실패한 입찰자가 다시 선택되지 않는다.

## 변경 파일

### common
- `bid_winner.proto`: `ReassignWinner` RPC + `ReassignWinnerRequest` 추가

### bid-service
- `BidStatus`: `DISQUALIFIED` 추가
- `Bid`: `disqualify()` (WINNER→DISQUALIFIED), `markWinner()` OUTBID→WINNER 허용
- `BidRepository`: `findFirstByAuctionIdAndStatusOrderByAmountDesc()` 차순위 조회
- `BidService`: `reassignWinner()` — 실격 + 승격 + 멱등
- `BidWinnerGrpcService`: `reassignWinner` 핸들러, 공통 응답 변환 `toGrpcResponse()` 추출

### auction-service
- `Auction`: `resetForReassignment()` — winnerId/price 초기화, reassignmentCount 증가
- `AuctionSettlementService`: `reassignWinner()`, `failAfterAllBiddersExhausted()`
- `AuctionEventProducer`: `publishReassigned()` WinnerReassignedEvent 발행
- `BidGrpcClient`: `reassignWinner()` gRPC 호출
- `PaymentEventConsumer`: `handlePaymentFailed()` 차순위 승계 로직 구현

### payment-service
- `AuctionWonEventConsumer`: `handleWinnerReassigned()` WinnerReassignedEvent 핸들러

## 설계 결정

- **DISQUALIFIED 상태**: OUTBID와 구분해 실패한 입찰자를 영구적으로 제외. 별도 제외 목록 관리 불필요.
- **컨슈머에서 gRPC 호출**: PaymentEventConsumer가 bid-service를 직접 호출. 스케줄러의 다음 틱을 기다리지 않고 즉시 승계. CB가 보호.
- **idempotencyKey**: `{auctionId}-{newWinnerId}-{reassignmentCount}` — 재지정마다 고유한 결제 생성.
- **reassignWinner 멱등성**: 이미 다른 WINNER가 지정되어 있으면 그대로 반환.

## 면접 포인트

- **왜 DISQUALIFIED?** OUTBID로 되돌리면 이전 실패자가 차순위 조회에 다시 잡힌다. 별도 상태로 영구 제외.
- **컨슈머에서 외부 호출 괜찮나?** 5초 데드라인 + CB로 보호. 실패 시 로그만 남기고 이벤트 재처리는 D12 DLQ에서.
- **연쇄 실패 무한루프?** 각 실패마다 한 명씩 DISQUALIFIED되므로 OUTBID가 고갈되면 종료(FAILED). 최대 입찰자 수만큼.
