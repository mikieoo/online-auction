# 0001: 로컬 환경 서비스별 DB 분리 방식

## 상황

MSA에서는 서비스별 독립 DB 인스턴스가 원칙이지만, 로컬 개발 환경에서 MySQL 인스턴스 3개를 동시에 운영하면 메모리 부담이 크다.

## 결정

하나의 MySQL 8.0 인스턴스에 3개 데이터베이스(auction_db, bid_db, payment_db)를 스키마로 분리한다.

## 대안

- MySQL 인스턴스 3개: 리소스 과다. 로컬 개발 환경에 부적합.
- H2 인메모리: MySQL과 방언 차이로 스키마 호환 문제 발생 가능.

## 결과

- 로컬에서는 단일 인스턴스로 개발 효율 확보.
- GKE 배포(D18) 시 Cloud SQL 인스턴스로 분리하여 MSA 원칙 준수.
- 로컬에서 서비스 A가 서비스 B의 DB에 접근하는 실수가 물리적으로 차단되지 않는다. 코드 리뷰로 방지.
