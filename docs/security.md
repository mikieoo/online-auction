# 보안 정책

## 인증 흐름

1. 클라이언트가 `Authorization: Bearer <JWT>`를 붙여 Gateway(8080)에 요청한다.
2. Gateway는 하류 서비스로 라우팅되는 **모든** 요청에서 클라이언트가 보낸 `X-User-Id` 헤더를 제거한다(공개 조회 포함).
3. 인증이 필요한 요청이면 토큰을 검증한다(HS256, 서명·만료, `sub`가 양의 정수인지).
4. 검증 성공 시 `X-User-Id = sub`를 붙여 내부 서비스에 전달한다. 내부 서비스는 토큰을 보지 않고 이 헤더만 신뢰한다.
5. 검증 실패 시 Gateway가 401로 응답하고 내부 서비스로 전달하지 않는다.

인증이 필요한 요청: `/api/**`의 GET이 아닌 모든 메서드, 그리고 `GET /api/v1/payments/**`. 그 외 GET(상품·경매·입찰 조회)은 공개이며, 토큰이 있어도 검증하지 않고 `X-User-Id`도 붙이지 않는다(만료된 토큰을 들고 있다는 이유로 공개 조회가 막히지 않게).

실패 경로: 헤더 없음·`Bearer` 형식 아님·서명 불일치·알고리즘이 HS256이 아님·`sub`가 `[1-9][0-9]*` 형태가 아님 → 401 `UNAUTHORIZED`. 만료 → 401 `TOKEN_EXPIRED`. 실패 사유(서명/형식/sub)는 메시지로 구분해 알려주지 않는다.

토큰: 클레임 `sub`(userId), `iat`, `exp`. 수명 기본 1시간(`gateway.jwt.ttl`). 리프레시 토큰·폐기(revocation) 없음 — 만료까지 유효하다.

## 토큰 발급

로그인·회원 서비스가 없다. 개발·시험용으로 Gateway에 `POST /auth/token {userId}`가 있으며, **비밀번호 없이 임의의 userId로 토큰을 발급한다.** 그래서 Spring 프로필 `local`이 활성일 때만 존재하고, 다른 프로필에서는 경로 자체가 404다. 운영 성격의 환경에서 `local` 프로필을 켜면 누구나 임의 사용자가 될 수 있다 — 켜지 않는다.

## 인가

| 동작 | 조건 |
|------|------|
| 상품 등록 | 인증된 사용자 |
| 경매 생성 | 해당 상품의 판매자(sellerId == userId). 아니면 403 |
| 경매 시작 | 해당 상품의 판매자(sellerId == userId). 아니면 403 |
| 입찰 | 인증된 사용자 AND sellerId != bidderId. 판매자 본인이면 403 |
| 상품·경매·입찰 조회 | 인증 불필요 (공개). 경매 응답에는 sellerId·startingPrice가 포함된다 |
| 결제 조회 | 인증된 사용자 AND 결제한 본인(payerId == userId). 아니면 403 |
| 낙찰 확정, 결제 생성 | 내부 API(`/internal/v1/**`). 사용자 인증 없음. Gateway에 라우트가 없어 8080으로는 404 |
| 토큰 발급 | `local` 프로필에서만 존재. 인증 없음 |

본인 경매 입찰은 명시적으로 거부된다. 별도 관리자 역할은 없다. 인증(토큰 유무)은 Gateway가, 소유권 기반 인가(판매자·결제자 본인 여부)는 각 서비스가 판단한다.

## 알려진 한계

- **공개 진입점은 8080뿐이지만 로컬에서는 서비스 포트(8081~8083)가 그대로 열려 있다.** 그 포트로 직접 호출하면 `X-User-Id`를 위조할 수 있고 `/internal/**`도 호출된다. 내부 서비스의 헤더 신뢰는 "Gateway 뒤에만 놓인다"는 전제이며, K8s(D18)에서 서비스들을 ClusterIP로만 노출해 해소한다.
- Actuator(`health`, `circuitbreakers`, `circuitbreakerevents`)가 gateway·auction·bid에 무인증으로 열려 있다. 로컬 한정이며, K8s에서는 management 포트를 분리해 외부에 노출하지 않는다.
- Eureka 대시보드·레지스트리(8761)도 무인증이다. 로컬 전용 모듈이다.

## 서비스 간 통신

서비스 간 내부 통신(REST/gRPC, Kafka)에는 별도 인증을 적용하지 않는다 (학습 프로젝트 범위). 내부 API는 `/internal/v1/` 경로로 분리해 Gateway가 외부에 노출하지 않는 것이 유일한 보호다. 프로덕션에서는 mTLS 또는 서비스 메시로 보호해야 한다.

## 민감 데이터

- DB 비밀번호는 로컬에서는 docker-compose.yml 환경 변수, GKE에서는 K8s Secret으로 관리.
- JWT 서명 키는 환경 변수 `JWT_SECRET`으로만 주입한다. 코드·설정 파일에 기본값을 두지 않으며, 없거나 32바이트 미만이면 Gateway가 기동에 실패한다. 테스트 전용 키는 테스트 코드 안에서만 쓴다.
- 결제 정보(payerId, 금액, 결과)는 본인 외에 조회할 수 없다. 오류 메시지에도 타인의 결제 내용을 담지 않는다.
